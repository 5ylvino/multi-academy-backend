# Multi-Academy backend

Monorepo for the Multi-Academy School Management System APIs.

Nest (`web-server`) is the authenticated school gateway. Python services own domain work. The control plane owns policy, feature flags, and provider secrets.

Target architecture: [PERFORMANCE_ARCHITECTURE.md](./PERFORMANCE_ARCHITECTURE.md).

Container development and production deployment: [DOCKER.md](./DOCKER.md).

## Services

| Directory | Port | Role | Local run |
|-----------|------|------|-----------|
| `control-system-server` | 8000 | Policy, flags, provider vault | [README](./control-system-server/README.md) |
| `web-server` | 8001 | Nest school API + thin edge | [README](./web-server/README.md) |
| `ai-service` | 8010 | RAG / LLM / timetable solver | [README](./ai-service/README.md) |
| `tutoring-service` | 8011 | Tutor marketplace | [README](./tutoring-service/README.md) |
| `payment-service` | 8012 | Checkout, webhooks, gateway rules | [README](./payment-service/README.md) |
| `portal-read-service` | 8013 | Cached portal dashboards | [README](./portal-read-service/README.md) |
| `worker-service` | 8014 | Async notifications + reports | [README](./worker-service/README.md) |

Typical start order: Redis + DBs → control (`8000`) → Nest (`8001`) → AI (`8010`) → payment (`8012`) → tutoring (`8011`) → portal-read (`8013`) → worker (`8014`) → client. Full dependency notes: [PERFORMANCE_ARCHITECTURE.md](./PERFORMANCE_ARCHITECTURE.md#local-start-order).

## Python services (`.pym`)

Each Python service uses a local venv named **`.pym`** and **Python 3.11**.

From that service directory:

```bash
python3.11 -m venv .pym
source .pym/bin/activate
python -m pip install -U pip
python -m pip install -e ".[dev]"   # or: python -m pip install -r requirements.txt
```

If `python3.11` is not on PATH (pyenv):

```bash
~/.pyenv/versions/3.11.15/bin/python -m venv .pym
```

- Recreate `.pym` after moving the folder — activate scripts store an absolute path.
- Run tools as `python -m pip` and `fastapi dev app/main.py --port <port>`. If pyenv intercepts `fastapi`, use `python -m fastapi`. Homebrew `pip` fails with `externally-managed-environment`.
- The module is `venv`; the folder is `.pym`. Do not run `python -m .venv venv`.
- Confirm the venv: `python -c "import sys; print(sys.executable)"` must contain `/.pym/`.
- `*.egg-info/` is generated by `pip install -e` and is not source.

## Nest

```bash
cd web-server
npm install
cp .env.example .env
npm run start:dev
```

API: `http://localhost:8001/api/v1`. Thin edge: `npm run start:edge:dev`.
